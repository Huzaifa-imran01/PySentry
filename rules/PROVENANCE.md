# Rule provenance and boundaries
Reviewed upstream: semgrep/semgrep-rules commit a5ad1714f00c9f7fde980cab0ea1d6dc6d414fd2, python/lang/security/audit/eval-detected.yaml.
The local insecure-eval check retains the pre-existing broad pattern rather than copying upstream exclusions or metadata. It flags constant eval too; this is an audit signal. No upstream code is vendored; other rules are original project rules. Live registry auto-updates are disabled.
Framework flow support: Flask request args/form/values/JSON/files and Django GET/POST/body. Analysis is intraprocedural; custom wrappers, cross-file authorization, generic business invariants, and deployment infrastructure are not covered. csrf_exempt is a CSRF configuration signal, NOT proof of missing authorization. DEBUG=True is a Python settings signal, NOT a complete deployment audit. MD5/SHA1 and hardcoded passwords are review signals, not proof of exploitability.
HTML escaping is recognized ONLY for HTML-marking sinks, never shell, SQL, paths, URLs, or template code. SQL taint focuses on query text, not bound values. URL taint focuses on the URL, not query parameters. No universal validate() sanitizer is assumed.
